# 🪙 ReflexCoin Tokenomics — Phase 1 Framework

ReflexCoin is an **ethical token** designed to reward contributors in the Reflexhon ecosystem while funding community education and AI development. This document outlines the Phase 1 prototype framework.

---

## 🎯 Core Principles

1. **Creator-First**: 80% of earnings go to contributors
2. **Treasury-Funded**: 20% funds community education & DAO governance
3. **Value-Aligned**: Only ethical contributions earn tokens (no harm, cultural respect)
4. **Transparent**: All allocations publicly auditable
5. **Sustainable**: No speculation; tokens tied to real contribution

---

## 💰 Token Fundamentals (Phase 1 Prototype)

### Token Supply
- **Initial Supply**: 10,000,000 ReflexCoin (prototype; adjustable post-audit)
- **Distribution**: Gradual release based on contribution validation
- **Circulating Supply**: Starts at 0; grows as contributors earn
- **Max Supply**: 100,000,000 (long-term cap to prevent inflation)

### Token Mechanics
- **Symbol**: `RFX`
- **Decimals**: 4 (support for micro-transactions)
- **Blockchain**: Pending (Phase 2) — Currently prototyped as database entries
- **Transfer**: Disabled in Phase 1 (non-tradeable until governance approved)

## 💵 Reward Distribution Model

### Earnings Split: Creator-First (80/20)

```
Contribution Value
    ↓
┌─────────────────────────┐
│  Creator Earnings: 80%  │  → Direct payment to contributor
├─────────────────────────┤
│ Treasury Fund: 20%      │  → Education + DAO operations
│ (2% Team, 18% DAO)      │
└─────────────────────────┘
```

**Example**: Artist sells prompt for 100 RFX
- Artist receives: 80 RFX ✓
- Treasury: 2 RFX (team operations)
- DAO education fund: 18 RFX

### Monthly Distribution Cycle
1. **Contribution submission** (Weeks 1–3)
2. **Validation & audit** (Week 3)
3. **DAO vote** (Week 4)
4. **Token distribution** (End of month)

## 🔐 Contribution Validation Framework

### Phase 1: Human-in-the-Loop Review

Before earning tokens, each contribution must pass:

#### 1. **Originality Check**
- No plagiarism (checked against CC-licensed databases)
- Proper attribution if derivative work
- Clear license declaration (CC-BY-4.0, MIT, etc.)

#### 2. **Quality Audit**
- Code: Functional, documented, follows project conventions
- Art: Meets design standards, professional quality
- Docs: Clear, accessible, factually accurate
- Prompt: Creative, useful, culturally appropriate

#### 3. **Ethics Validation**
- ✅ Does NOT discriminate against any group
- ✅ Respects local languages & cultural norms
- ✅ Transparent about data sources
- ✅ No bias toward/against marginalized communities
- ✅ Contributor follows CODE_OF_CONDUCT

#### 4. **DAO Vote** (for high-impact contributions)
- Contributions > 500 RFX require community vote
- Simple majority (50% + 1) approval needed
- Voting power: 1 vote per holder (early phase) → upgrades in Phase 2

## 📊 Treasury Allocation (20% Fund)

Monthly treasury receives ~2% of all token earnings.

### Allocation Strategy

```
Monthly Treasury (100%)
├── 10% → Education Programs (global + local hubs)
├── 30% → DAO Operations (voting incentives, moderation)
├── 25% → Developer Infrastructure (servers, tools, APIs)
├── 20% → Community Outreach (events, partnerships)
├── 10% → Research & Innovation (new features, R&D)
└── 5% → Emergency Reserve (security, unexpected needs)
```

**Example**: If 10,000 RFX earned in a month → 2,000 RFX treasury
- Education: 200 RFX → Local Papiamentu AI workshops
- DAO: 600 RFX → Voting incentives for governance
- Infrastructure: 500 RFX → Google Cloud, HuggingFace hosting
- Outreach: 400 RFX → Community events, grants
- Innovation: 200 RFX → Prototype new features
- Reserve: 100 RFX → Contingency fund

## ⚠️ Risk Management

### Phase 1 Safeguards
1. **No real money exchange**: Tokens prototype only
2. **Withdrawal limits**: Max 500 RFX/month during pilot (prevent gaming)
3. **Contribution caps**: Single contribution max 5,000 RFX (audit scalability)
4. **Community veto**: DAO can reject suspicious patterns

### Fraud Prevention
- Require video introduction from new contributors
- Cross-check duplicates (same person, multiple accounts)
- Track contribution timestamps (prevent bulk submissions)
- Periodic random audits of high-value claims
